“파일이 안 열려요”라는 답장을 받았다면 같은 메일을 그대로 다시 보내기 전에, 상대가 어디에서 막혔는지부터 확인해요. 파일 자체가 없는지, 링크에서 권한을 요구하는지, 내려받은 파일을 앱이 읽지 못하는지에 따라 고칠 곳이 달라요. 보낸편지함에서 실제 발송된 메일을 열고 순서대로 확인하면 돼요.

이 글은 첫 업무메일에서 자주 만나는 첨부파일·Google Drive·OneDrive 링크 문제를 다뤄요. 2026년 10월 9일 확인한 공식 안내를 바탕으로 썼고, 메뉴 이름과 사용 가능한 기능은 앱 버전·계정·회사 정책에 따라 달라질 수 있어요. 예문과 파일명은 모두 가상 예시예요. 회사가 정한 파일 전달·외부 공유 절차를 먼저 따라요.

1. “안 열린다”를 네 가지 상황으로 나눠요

  • 메일에 파일이나 링크가 없어요: 보낸편지함에서 첨부 누락 여부를 확인해요. 작성창에 올리려던 파일과 실제 발송된 파일은 다를 수 있어요.
  • 링크를 눌렀더니 “액세스 권한 필요”가 나와요: 공유 대상 주소, 로그인한 계정, 회사의 외부 공유 제한을 확인해요.
  • 다운로드는 됐는데 파일이 안 열려요: 파일 형식, 사용하는 앱, 파일 손상 가능성, 보안 차단 문구를 확인해요.
  • 파일은 열리지만 내용이 예전 것이에요: 첨부한 사본과 공유 문서 중 어느 것을 보냈는지, 필요한 수정이 실제 배포본에 들어 있는지 확인해요.

처음에는 “첨부가 보이지 않는지, 링크를 누르면 권한 요청이 뜨는지 알려 주실 수 있을까요?”처럼 범위를 좁혀 물어봐요. 화면이 필요하면 오류 문구가 있는 부분만 부탁하세요. 메일함 전체, 다른 고객 이름, 문서 본문이 함께 보이는 캡처는 받을 필요가 없어요. 비밀번호나 인증번호도 요청하지 마세요.

2. 첨부한 사본인지 원본으로 가는 링크인지 봐요

일반 첨부파일은 그 시점의 파일 사본을 메일에 넣어 보내는 방식이에요. 발송한 뒤 내 컴퓨터에서 원본을 수정해도 이미 보낸 사본은 바뀌지 않아요. Outlook 공식 안내도 사본으로 보낸 파일의 수정 내용이 OneDrive·SharePoint 원본과 동기화되지 않는다고 설명해요. 숫자를 고친 뒤 예전 첨부 메일만 다시 전달했다면 수정본이 전해진 것이 아니에요.

Drive나 OneDrive 링크는 온라인에 있는 문서로 들어가는 주소예요. 공동으로 내용을 고칠 때 편하지만, 링크를 아는 것과 열 수 있는 권한은 따로 확인해야 해요. 또 같은 이름의 파일을 새로 만들었다면 이전 링크가 새 파일을 가리킨다고 생각하지 마세요. 보낸 메일의 링크를 직접 눌러 제목과 본문을 확인해요.

  • 상대가 제출 시점의 내용을 보관해야 해요: 회사가 허용하는 형식의 배포용 사본을 준비하고 기준 날짜·버전을 적어요.
  • 같은 문서에서 계속 검토해야 해요: 회사에서 쓰는 공유 문서 링크를 보내고 필요한 보기·댓글·편집 권한을 정해요.
  • 첨부와 링크를 함께 보내요: “첨부 PDF는 이번 검토본, 링크는 이후 수정사항 반영용”처럼 각 자료의 용도를 분명히 써요.

개인 Gmail 계정은 첨부파일 크기 제한이 25MB예요. 직장·학교 계정은 Google Workspace 관리자가 전송·수신 제한을 설정해요. 공식 안내에 따르면 총 첨부 크기가 제한을 넘으면 Gmail이 첨부파일 대신 Drive 링크를 넣어요. 파일을 끌어 넣었더라도 발송 직전에는 어떤 방식으로 표시되는지 확인하세요.

3. 권한은 실제 수신자 주소에 맞춰요

내 화면에서 링크가 열리는 것만으로 수신자의 접근을 확인할 수는 없어요. 나는 소유자이거나 이미 권한을 가진 사람이기 때문이에요. 로그인하지 않은 창에서 안 열리는 것도, 특정 계정만 허용한 파일이라면 정상일 수 있어요. 시험 삼아 업무파일을 개인 계정으로 보내지 말고 공유 설정과 승인된 수신자 계정을 대조해요.

  1. 보낸편지함에서 실제 링크를 열어 공유할 파일이 맞는지 확인해요. 비슷한 이름의 폴더나 작업 중인 원본을 보냈는지도 살펴요.
  2. 파일의 공유 설정을 열고 메일의 받는 사람 주소와 허용된 사용자 주소를 대조해요. 자동완성된 동명이인이나 예전 주소를 선택하지 않았는지 확인하세요.
  3. 승인된 수신자에게 필요한 수준만 지정해요. 읽기만 필요하면 뷰어, 의견을 남겨야 하면 댓글 작성자, 내용을 직접 바꿔야 하면 편집자를 검토해요.
  4. 적용 후 공유 설정을 다시 열어 주소와 권한이 반영됐는지 확인해요. 수신자에게는 공유받은 계정으로 링크를 다시 열어 달라고 안내해요.

회사 메일로 공유했는데 상대 브라우저가 개인 Google 계정으로 로그인돼 있으면 권한 오류가 날 수 있어요. Google은 여러 계정을 쓰는 경우 파일을 공유받은 계정인지 확인하도록 안내해요. 상대가 액세스를 요청했더라도 표시된 요청자 주소를 확인하고 승인하세요. 요청이 왔다는 이유만으로 처음 보는 계정에 권한을 주지는 마세요.

Outlook에서 OneDrive·SharePoint 파일을 보낼 때도 링크의 액세스 관리 또는 권한 메뉴를 확인해요. 사본으로 첨부할 수 있는 경우도 있지만, 회사가 외부 공유를 제한한 파일을 사본으로 바꿔 보내면 된다고 단정해서는 안 돼요. 조직 정책에 막힌 경우에는 담당자에게 허용된 전달 방법을 확인해요.

급해도 “링크가 있는 모든 사용자”부터 켜지 마세요

Google 안내에서 이 설정은 메일을 전달받은 사람도 링크로 접근할 수 있는 방식이에요. 업무자료를 누구에게 보여 줄지 먼저 정하고 필요한 사람에게만 공유하세요. 한 파일을 보내려다 폴더 전체를 열지 않도록 범위도 확인해요. 상위 폴더 권한이 파일에 이어지는 경우가 있으니, 공유 범위가 예상보다 넓다면 소유자나 관리자와 함께 정리해요.

4. 내려받은 파일이 안 열리면 형식과 오류를 확인해요

  1. 보낸편지함의 첨부파일을 회사가 허용하는 위치에 내려받아 직접 열어 봐요. 원본만 열어 보고 첨부된 파일도 같을 것이라고 넘기지 마세요.
  2. 상대에게 필요한 형식과 지금 보낸 확장자가 맞는지 확인해요. 확장자는 파일 이름 끝의 .pdf, .docx 같은 부분이에요. 이름 끝만 바꾸는 것은 형식 변환이 아니에요.
  3. 미리보기만 안 되는지, 내려받은 뒤 해당 앱에서도 안 되는지 구분해요. 오류 문구와 사용하는 앱 이름을 확인하면 담당자가 원인을 찾기 쉬워요.
  4. 읽기용 자료라면 허용되는 경우 PDF 사본을 새로 만들 수 있어요. 변환한 뒤 글자, 표, 페이지 누락을 확인하세요. 수식이나 편집이 필요한 업무는 PDF만으로 해결되지 않을 수 있어요.

보안상 차단되었다는 메시지라면 확장자를 속이거나 보안 기능을 끄라고 안내하지 마세요. Gmail은 실행파일 등 일부 유형의 첨부를 제한해요. 업무상 꼭 필요한 파일이라면 오류 문구와 파일 종류를 사내 지원 담당자에게 전달하고 승인된 방법을 사용해요. 무료 변환 사이트에 회사자료를 올리는 것도 별도 외부 전송이라는 점을 기억하세요.

5. 파일명보다 안의 내용으로 버전을 확인해요

“최종”, “진짜최종”이라는 이름만으로는 어떤 수정이 들어갔는지 알기 어려워요. 예를 들어 ‘행사안내_20261009_v02_검토용.pdf’처럼 날짜와 버전을 넣되, 날짜가 행사일인지 작성일인지 팀 안에서 정해요. 파일명은 찾기 위한 표시이고 최종 확인은 본문에서 해요.

  • 최근 요청받은 수정 한두 곳이 실제 첨부파일 또는 링크 문서에 반영돼 있어요.
  • 문서 첫 페이지, 표 안의 날짜, 파일명에 적힌 기준이 서로 맞아요.
  • 검토용과 외부 배포용을 구분했고, 아직 승인받지 않은 자료를 확정본처럼 표시하지 않았어요.
  • 메일 본문에 적힌 파일 수와 실제 첨부 수가 같고, 여러 파일 중 사용할 버전이 분명해요.

6. 받을 필요 없는 정보가 들어 있지 않은지 봐요

첨부파일을 열었을 때 바로 보이는 본문만 확인하지 마세요. 다른 고객의 연락처, 주민등록번호, 계좌정보, 내부 검토 의견처럼 이번 수신자가 받을 필요 없는 내용이 섞였는지 살펴요. 화면에서 행이나 시트를 숨겨 둔 상태를 정보 삭제로 생각하지 말고, 배포에 필요한 내용만 담긴 사본을 준비하세요.

Microsoft의 문서 검사 기능은 댓글, 수정 흔적, 문서 속성 등 숨은 정보를 찾는 데 도움이 돼요. 지원되는 데스크톱 Office에서는 파일의 정보 메뉴에서 문제 확인, 문서 검사를 찾아볼 수 있어요. 제거한 내용을 복구하지 못할 수 있으므로 원본을 보관하고 사본에서 검사해요. 기능이 모든 정보를 찾아 없애 주는 것은 아니니 결과를 검토하고 배포본을 다시 열어 확인하세요.

안전한 공유 권한을 설정했더라도 잘못된 내용이 담긴 파일을 보내면 문제는 남아요. 반대로 내용이 정리됐어도 수신자나 공유 범위를 잘못 잡으면 노출될 수 있어요. 자료 내용, 받는 사람, 접근 범위를 각각 확인하는 습관을 들여요.

7. 다시 보낼 때는 바뀐 점과 사용할 자료를 적어요

문제를 고쳤다면 기존 대화 흐름에서 필요한 사람에게 알려요. 이유를 길게 설명하기보다 어떤 조치를 했고, 어느 파일을 열면 되고, 추가 확인이 필요한지를 적으면 돼요. 아래 문장은 실제 상황에 맞게 바꿔 쓰는 예시예요. 아직 하지 않은 조치를 완료했다고 적지 마세요.

“앞선 메일에 첨부가 누락되어 행사 안내 PDF 1개를 다시 보냅니다. 이번 메일의 ‘행사안내_20261009_v02_검토용.pdf’를 확인해 주세요. 번거롭게 해 드려 죄송합니다.”

예전 버전을 보낸 경우

“앞서 보낸 파일에서 장소 변경사항이 빠진 것을 확인해 수정본을 다시 보냅니다. 이번 첨부파일의 2쪽에 변경사항을 반영했습니다. 이전 첨부파일 대신 이번 파일을 기준으로 검토해 주세요.”

권한을 바꾼 것과 상대가 실제로 열어 본 것은 다른 상태예요. “이제 무조건 됩니다”라고 쓰기보다 내가 확인한 조치를 말해요. 검토나 제출 마감이 걸린 파일이라면 수신자가 열 수 있는지까지 확인하고, 장애로 일정이 달라질 수 있으면 담당자에게 현재 상태를 알려요.

8. 잘못된 사람에게 보냈다면 일반 재발송과 다르게 처리해요

비공개 정보가 포함된 자료를 엉뚱한 사람에게 보냈다면 조용히 수정본만 보내고 끝내지 마세요. 회사의 사고 보고 절차에 따라 담당자에게 즉시 알리고, 보낸 시각·수신자·파일·현재 공유 상태를 정리해요. 공유 링크의 접근 차단 등 가능한 조치는 권한과 사내 절차에 따라 진행하고 확인된 결과를 남겨요.

링크 권한을 없애더라도 이미 내려받거나 복사한 자료까지 회수되는 것은 아니에요. 일반 첨부파일도 내 보낸편지함에서 지웠다고 상대의 사본이 사라졌다고 볼 수 없어요. “삭제했으니 괜찮다”고 단정하거나 기록을 없애지 말고, 수신자에게 보낼 정정·삭제 요청은 담당자와 내용 및 절차를 맞춰요.

마지막으로 보낸 메일 기준으로 확인해요

  • 첨부 사본과 공유 링크 중 무엇을 보냈는지 확인했어요.
  • 실제 수신자 주소와 권한이 맞고, 필요한 수준으로만 공유했어요.
  • 메일에 들어간 파일을 열어 내용·버전·개인정보를 확인했어요.
  • 재발송했다면 바뀐 점과 이제 사용할 자료를 분명히 적었어요.
  • 열람 문제와 별개로 정보 노출이 있었다면 정해진 보고 절차를 따랐어요.

파일 전달은 보내기 버튼을 누른 뒤에도 한 번 더 확인할 일이 있어요. “내가 보냈다”에서 한 걸음 더 가서, 필요한 사람이 허용된 방식으로 맞는 자료를 사용할 수 있는지 확인해 보세요. 다음에 같은 문제가 생기면 보낸편지함, 전달 방식, 계정과 권한, 실제 파일 내용 순서로 돌아오면 돼요.
