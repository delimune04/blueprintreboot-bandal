UK Data Service는 자료를 안전하게 보관하고 정기적으로 백업하며, 이름과 버전을 일관되게 관리하도록 안내해요. 개인 과제에도 같은 원칙을 적용할 수 있어요. 파일이 있다는 것뿐 아니라 다시 열 수 있는지도 확인해요.

폴더 세 개로 시작해요

  • 원본: 받은 자료와 직접 수집한 기록을 보관해요.
  • 작업: 수정 중인 문서와 분석 파일을 두고 날짜나 버전을 붙여요.
  • 제출: 실제로 낸 파일과 제출 확인 화면을 함께 남겨요.

예를 들어 “환경과학_보고서_20260911_v03”처럼 이름을 정하면 나중에 찾기 쉬워요. 공동 작업 자료에는 누가 어떤 부분을 바꿨는지 짧게 기록해요. 개인정보가 든 자료는 공유 대상을 제한해요.

  • 원본을 수정하지 않고 작업 사본을 만들었어요.
  • 중요한 파일을 별도 저장 위치에도 백업했어요.
  • 백업 파일을 실제로 열어 내용이 맞는지 확인했어요.
  • 제출한 버전과 제출 확인 기록을 함께 보관했어요.

밤새 고친 보고서가 사라졌거나, 제출하고 나서 예전 파일을 올렸다는 사실을 알아차리면 무엇부터 해야 할지 막막해요. 파일 관리는 이런 순간에 돌아갈 지점을 남기는 일이에요. 원본·작업본·제출본을 구분하고, 중요한 시점의 사본을 다른 곳에 보관하며, 그 사본이 실제로 열리는지 확인하는 것부터 시작하세요.

이 글의 과목명·날짜·파일명·대화는 이해를 돕기 위한 가상 예시예요. 실제 학생의 과제나 개인정보는 사용하지 않았어요. 제품 안내는 2026년 10월 6일 공식 도움말을 확인했어요. 화면의 메뉴 이름은 언어와 앱 버전에 따라 다를 수 있고, 학교 계정의 기능·보관 기간은 학교 설정에도 영향을 받아요.

1. 이미 실수했다면, 지금 할 일부터 골라요

문제가 난 파일을 계속 고치거나 같은 이름으로 저장하기 전에 잠깐 멈추세요. 현재 남아 있는 내용을 다른 이름의 사본으로 확보할 수 있다면 먼저 보관해요. 파일명, 저장한 서비스와 계정, 마지막으로 정상 내용을 본 시각을 적으면 복구할 대상을 찾기 쉬워요. 복구를 시도하는 동안 휴지통 비우기와 오래된 버전 삭제는 미뤄 두세요.

  • 파일을 삭제했어요: 개인 계정과 학교 계정 중 어디에 저장했는지 확인하고 해당 서비스의 웹 휴지통을 열어요. 컴퓨터에서 직접 지운 파일은 운영체제 휴지통도 확인해요. 공유받은 파일이면 소유자가 삭제하거나 접근 권한을 바꾼 것은 아닌지 구분해요.
  • 내용이 예전 것으로 덮였어요: 파일 자체가 남아 있다면 버전 기록에서 실수 직전의 내용을 찾아요. 날짜가 비슷한 버전을 바로 복원하지 말고 필요한 문장·표가 있는지 먼저 봐요. 사본을 만들 수 있으면 그 사본에서 비교해요.
  • 다른 파일을 제출했어요: 제출 화면과 현재 첨부파일을 먼저 확인해요. 재제출 가능 여부와 마감 규칙을 확인하고, 가능하면 올바른 파일로 다시 제출한 뒤 결과를 열어 봐요. 잠긴 경우에는 담당자에게 과목·과제명, 제출 시각, 잘못 올린 사실과 수정 파일을 전달할 공식 경로를 확인해요. 재제출이나 점수 인정이 자동으로 보장되지는 않아요.
  • 저장 중인데 인터넷이 끊겼어요: 내용이 보이는 창을 성급하게 닫지 말고, 가능한 범위에서 다른 이름 저장이나 로컬 사본으로 보존해요. 브라우저의 사이트 데이터 삭제나 앱 재설치부터 하지 마세요. 연결이 돌아오면 저장 상태와 웹에 보이는 내용을 대조해요.
  • 앱이 갑자기 종료됐어요: Office의 자동 복구가 켜져 있었다면 앱을 다시 열 때 문서 복구가 나타날 수 있어요. 열리는 복구본을 다른 이름으로 저장하고 마지막 문단을 확인해요. 자동 복구가 모든 편집을 남기는 것은 아니에요. Microsoft의 저장·백업·복구 안내를 확인하세요.
Microsoft의 저장·백업·복구 안내

2. 저장·동기화·백업·버전 기록을 구분해요

저장은 지금 편집한 내용을 파일에 반영하는 일이에요. 동기화는 여러 기기와 온라인 저장소의 상태를 맞추는 기능이에요. 백업은 원래 파일이 없어지거나 망가졌을 때 돌아갈 수 있도록 사본을 따로 보관하는 일이에요. 버전 기록은 같은 파일이 바뀌어 온 이전 상태를 찾아보는 기능이고, 휴지통은 삭제한 파일을 일정 조건 안에서 되돌리는 공간이에요.

문서가 어제 내용으로 바뀌었다면 버전 기록, 파일 자체를 지웠다면 휴지통부터 찾아요. 둘 다 없으면 별도 백업과 공유 상대가 가진 허용된 사본을 확인해요. 버전 기록도 계정 접근, 보관 정책, 기록 삭제의 영향을 받으므로 영구 보관함처럼 믿지는 마세요. “클라우드에 있어요” 다음에는 “어느 계정에, 어떤 복구 수단으로 남아 있나요?”를 확인해요.

3. 원본·작업·제출 폴더 세 개로 시작해요

가상 과제 폴더 “2026-2_환경과학_보고서” 안에 “01_원본”, “02_작업”, “03_제출”을 만들어요. 과목별로 같은 구조를 쓰면 바쁜 날에도 저장 위치를 고민하는 시간이 줄어요. UK Data Service의 폴더 구성 안내도 작업 단계가 다른 자료를 나누고 간단한 구조를 일관되게 쓰도록 권해요.

UK Data Service의 폴더 구성 안내
  • 원본: 교수자가 준 과제 설명, 내려받은 공개 자료, 처음 작성한 관찰 기록을 보관해요. 표를 정리하거나 숫자를 바꿀 때는 작업 폴더로 복사해서 수정해요. 원본 파일을 열었다면 저장 위치를 다시 확인하세요.
  • 작업: 문장 수정, 계산, 그림 편집을 하는 파일을 둬요. 보고서에 연결되는 표나 이미지도 같은 과제 폴더 안에서 정리해요. 사진의 위치가 바뀌면 편집 파일에서 연결이 끊길 수 있으므로 필요한 자료를 함께 남겨요.
  • 제출: 실제 제출한 파일과 제출 완료 기록을 보관해요. 작업본에서 고친 내용이 제출본에 자동 반영됐다고 생각하지 말고, 다시 내보낸 파일을 열어 확인하세요. 정정 제출을 했다면 처음 낸 것과 다시 낸 것을 구분해 둬요.

다운로드 폴더의 첨부파일은 과제 폴더로 복사한 뒤 수정하세요. 받은 양식은 원본으로 보관하고 작업 사본에 과제명을 붙여요. 원본과 작업 자료를 분리하는 이유는 실수로 덮어쓰더라도 처음 상태로 돌아갈 기준을 남기기 위해서예요.

원본과 작업 자료를 분리하는 이유

4. 파일명은 날짜와 버전의 뜻을 먼저 정해요

가상 파일명 “환경과학_보고서_20261006_v03.docx”에서 앞부분은 과목과 결과물, 날짜는 그 사본을 만든 날, v03은 세 번째로 구분해 남긴 버전이에요. v는 version, 즉 버전을 줄인 표시예요. 날짜를 자료 수집일로 쓸지 수정본 생성일로 쓸지 팀 안에서 맞춰 두세요.

가상 예시로 v01은 초안, v02는 참고문헌 추가, v03은 표 수치 확인까지 끝낸 상태로 정해요. 숫자를 두 자리로 맞추면 v02와 v10을 비교하기 쉬워요. 매번 띄어쓰기 한 칸을 고칠 때마다 사본을 만들기보다는 구조를 크게 바꾸기 전, 피드백 반영 후, 제출 직전에 남겨요. 간단한 변경 기록에 “v03: 표 2의 단위 수정”처럼 한 줄을 붙이면 이름만 봐서는 알 수 없는 차이를 설명할 수 있어요. UK Data Service의 버전 관리 안내를 과제에 맞춰 적용한 방법이에요.

UK Data Service의 버전 관리 안내

파일명 끝의 .docx, .xlsx, .pdf는 파일 형식을 나타내는 확장자예요. 이름의 .docx를 .pdf로 고치는 것만으로 PDF로 변환되지는 않아요. 앱의 내보내기나 다른 이름으로 저장에서 형식을 선택해요. 제출 규칙에 파일명이나 형식이 정해져 있다면 그 규칙을 우선하고, 내 작업용 버전 이름은 작업 폴더 안에 남겨요. 파일명에는 비밀번호나 불필요한 개인정보를 넣지 마세요.

5. 동기화가 잘돼도 별도 백업을 남겨요

같은 동기화 폴더가 노트북과 클라우드에 보인다고 해서 서로 독립된 두 백업이 되는 것은 아니에요. Google Drive에서 컴퓨터와 미러링·스트리밍하는 파일을 휴지통으로 옮기면 다른 위치에도 삭제가 반영돼요. OneDrive도 동기화 폴더에서 지운 파일이 온라인과 컴퓨터 양쪽에서 없어질 수 있어요. Google Drive 삭제 안내와 OneDrive 삭제 안내를 확인하세요.

Google Drive 삭제 안내OneDrive 삭제 안내

과제용으로는 작업 위치를 하나 정하고, 중요한 시점에 별도 위치로 날짜가 붙은 사본을 복사하는 방법이 단순해요. 예를 들어 학교에서 허용하는 클라우드에 작업본을 두고, 본인이 보관해도 되는 과제의 제출 전 사본을 외장 저장장치에도 보관할 수 있어요. 연구실·수업의 반출 제한이 있는 자료는 학교가 승인한 저장소와 백업 방식부터 확인하세요. 개인 계정으로 무조건 옮기는 방식은 피하세요.

다른 폴더라도 같은 노트북 안에만 있다면 기기 분실에 함께 영향을 받아요. 같은 가방에 노트북과 외장장치를 넣어 두면 가방을 잃을 때 함께 없어질 수도 있어요. 가상 예시로 “매주 금요일과 제출 직전, 허용된 별도 저장 위치에 사본 만들기”처럼 내가 지킬 수 있는 기준을 정해요. 대규모 편집을 시작하기 전에도 사본 하나를 남겨 두면 좋아요.

6. 백업한 파일을 직접 열어 봐야 끝나요

백업 폴더에 파일명이 보이는 것만으로 확인을 마치지 마세요. UK Data Service의 저장·보안 안내는 별도 위치의 여러 사본, 정기 백업, 복원 절차 점검을 권해요. 학생 과제에서는 중요한 파일 몇 개를 실제로 열어 보는 작은 점검부터 해도 돼요.

UK Data Service의 저장·보안 안내
  • 백업 위치로 직접 들어가 파일을 열어요. 최근 문서 목록은 원래 작업본을 열 수 있으니 파일의 위치를 확인하세요.
  • 보고서는 첫 장과 마지막 문단, 표의 단위, 참고문헌이 있는지 봐요. 가상 예시로 v03에 추가한 결론 문장이 백업본에도 있어야 해요.
  • 계산 파일은 시트 수, 핵심 수식과 결과를 확인해요. Microsoft의 CSV 저장 안내에 따르면 CSV는 현재 시트만 저장하고 서식은 보존하지 않으므로 편집용 원래 파일도 남겨요.
  • 압축파일은 별도 시험 폴더에 풀어 봐요. 연결된 이미지·자료가 빠지지 않았는지 확인하고, 시험 중 원본을 덮어쓰지 않아요.
Microsoft의 CSV 저장 안내

클라우드 문서의 바로가기나 주소만 저장하면 파일 내용 자체를 보관한 것과 달라요. 필요한 경우 내려받기가 허용된 문서를 실제 파일 형식으로 저장하고 열어 보세요. PDF는 제출 화면 확인에 편하지만 나중에 표를 수정하려면 편집용 파일도 필요할 수 있어요. 가상 점검 메모 “10월 6일: 보고서 PDF와 편집본 열림, 표 2·결론 확인” 정도면 다음 점검 때 도움이 돼요.

7. Google Docs의 이전 내용은 문서 안에서 찾아요

Google 문서·스프레드시트·프레젠테이션은 컴퓨터에서 파일을 열고 오른쪽 위 최종 수정·버전 기록 아이콘을 눌러요. 오른쪽 목록에서 시각과 변경 내용을 확인한 뒤 원하는 버전을 선택하고 “이 버전 복원하기”로 돌아갈 수 있어요. 이전 버전 옆 더보기에서 “사본 생성”을 선택하면 현재 문서를 바로 되돌리기 전에 따로 비교할 수 있어요. Google의 버전 기록 절차에 따른 방법이에요.

Google의 버전 기록 절차

이전 버전을 보려면 해당 파일의 수정 권한이 필요해요. 보기나 댓글 권한만 있다면 소유자에게 필요한 시점의 사본 또는 복구를 요청하세요. 일부 수정 기록은 묶일 수 있어요. 중요한 단계에 버전 이름을 붙이면 해당 버전이 병합되지 않도록 할 수 있지만, 계정 접근이나 파일 자체가 영원히 유지된다는 뜻은 아니에요. 문서당 이름 지정은 최대 40개, 스프레드시트는 최대 15개라는 제한도 있어요.

이 일반 파일의 이전 버전은 30일이 지났거나 더 새로운 버전이 100개 생기면 삭제될 수 있어요. Google 문서·시트·슬라이드에도 같은 30일·100개 규칙을 적용하면 안 돼요. “영구 보관”은 선택한 버전의 자동 정리를 막는 설정이며, 계정이나 파일의 모든 삭제 상황에서 복구를 보장하는 별도 백업은 아니에요. 가상 예시로 제출 PDF를 교체하기 전 중요한 이전 PDF를 내려받아 내용을 확인하고 따로 보관해요.

9. Google Drive에서 삭제했다면 계정별로 확인해요

Google Drive의 삭제 파일 복구 안내

개인 Google 계정은 위 도움말에 본인 계정으로 로그인해 복구 요청 경로가 제공되는지 확인할 수 있어요. 휴지통 밖 파일의 복구 가능 여부와 결과는 보장되지 않아요. 학교 Google Workspace 계정은 학교 관리자에게 바로 문의하세요. 일반 사용자 휴지통과 별도로, 관리자가 휴지통에서 영구 삭제된 Drive 데이터를 복구할 수 있는 기간은 25일 이내로 안내돼요. “30일에 25일을 더하면 누구나 55일 동안 안전하다”는 뜻이 아니에요.

이 Google Workspace 관리자 복구는 권한 있는 관리자가 진행해요. 선택한 기간에 삭제된 데이터를 함께 복원하는 방식이며 개별 파일만 지정하는 절차가 아니에요. 용량 제한 등으로 복원이 중단될 수 있고, 반영에 며칠이 걸릴 수 있어요. 공유 드라이브나 삭제된 사용자 계정은 별도 절차이므로 내 학교 계정 파일과 혼동하지 마세요. 파일명·원래 위치·삭제 추정 시각을 먼저 전달하고 비밀번호는 보내지 않아요. 복구 뒤에는 공유를 다시 설정해야 할 수 있으니 필요한 사람이 파일을 열 수 있는지도 확인하고, 기존에 허용된 대상과 권한 범위 안에서 공유를 복원하세요.

11. 오프라인에서 열리는지, 온라인에도 저장됐는지 확인해요

노트북에 파일명이 보인다고 파일 내용까지 내려받아진 것은 아니에요. OneDrive의 파란 구름 표시는 온라인 전용이라 인터넷 없이 열 수 없어요. 필요한 파일은 “항상 이 장치에 유지”로 내려받고 완료 상태를 확인하세요. 회전 화살표는 동기화 중, 빨간 오류 표시는 동기화 문제를 뜻해요. OneDrive 아이콘 설명에서 내 화면의 상태를 확인해요. 장치에 유지한 파일도 동기화 대상이므로 별도 백업과 같지는 않아요.

Google 문서의 컴퓨터 오프라인 사용은 인터넷이 있을 때 미리 설정해요. Chrome 또는 Edge, 오프라인 확장 프로그램, 저장 공간이 필요하고 시크릿 창은 사용하지 않아요. Drive 설정에서 오프라인을 켠 다음 필요한 파일의 “오프라인으로 사용”을 선택하고 문서 제목 옆 상태를 확인해요. 학교 관리자가 막아 둔 계정은 사용할 수 없어요. Google의 오프라인 사용 안내를 확인하세요.

Google의 오프라인 사용 안내

12. 팀플에서는 합칠 사람과 제출할 파일을 정해요

공통 편집 문서의 위치, 큰 수정 전 버전 이름, 합본 담당자, 제출 담당자를 처음에 정해요. 가상 대화 “오늘 20시부터 표를 합칠게요. 문장 수정은 20시 30분까지 멈추고, 새 의견은 댓글로 남겨 주세요”처럼 시간과 범위를 말하면 복원 도중 서로의 수정이 섞이는 일을 줄일 수 있어요.

다른 사람이 저장한 최신본을 내가 가진 구버전으로 통째로 덮어쓰지 않아요. 두 사본이 생겼다면 파일명과 수정 시간을 비교하고, 각자 수정한 부분을 확인한 뒤 필요한 내용을 합쳐요. 수정 시간이 더 늦다는 이유만으로 내용도 더 완성됐다고 단정하지 마세요. 복구 후에는 빠진 표·댓글·참고문헌이 없는지 함께 점검해요. “복원 버튼을 눌렀다”와 “팀이 사용할 내용이 맞다”는 각각 확인해야 할 일이에요.

공유 링크는 실제 필요한 사람에게 필요한 권한으로 전달해요. 사례 설명용 파일에 실제 학번, 연락처, 설문 응답자 정보, 연구실 기밀을 넣지 않아요. 졸업이나 수강 종료 전에 학교 계정의 사용 종료일과 자료 보관·반출 규정을 확인하고, 본인이 보관할 수 있는 자료만 승인된 방법으로 옮기세요. 학교 계정을 나중에도 계속 쓸 수 있다고 가정하지 않는 편이 좋아요.

13. 제출 직후 2분을 마지막 확인에 써요

제출 전 작업본에서 필요한 형식으로 내보낸 다음, 내보낸 파일을 다시 열어요. PDF라면 페이지 수·표 잘림·글꼴·참고문헌을 보고, 편집 파일이라면 요구한 형식이 맞는지 확인해요. 제출용 폴더에 후보 파일이 여러 개 있다면 이번에 낼 파일을 먼저 특정하세요. 가상 예시로 “v03의 표 수정이 들어간 8쪽 PDF”처럼 확인할 특징을 하나 정하면 구버전을 고르기 어려워져요.

LMS는 학교의 온라인 강의·과제 제출 시스템을 뜻해요. 업로드 표시만 보지 말고 제출 완료 상태, 첨부파일 이름, 제출 시각을 확인하세요. LMS에서 내려받을 수 있다면 제출한 파일을 다시 받아 열어 봐요. 완료 화면이나 접수 기록은 제출본 옆에 보관하되, 공유할 때는 이름·학번·다른 수업 정보가 노출되지 않도록 해요. 링크로 제출했다면 지정된 수신자가 열 수 있는 권한도 확인해야 해요.

14. 오늘은 파일 하나로 점검해 봐요

정리할 파일이 많다면 이번 주에 낼 과제 하나부터 해요. 원본을 남기고 작업 사본을 만든 다음, 제출 후보를 따로 저장하고, 허용된 별도 위치에 복사해 실제로 열어 보세요. 백업 일정은 공부를 끝내고 노트북을 닫기 직전처럼 이미 하는 행동에 붙이면 기억하기 쉬워요. 다음 네 문장을 실제로 확인한 뒤 체크해요.

  • 원본을 수정하지 않고 작업 사본을 만들었어요.
  • 중요한 파일을 별도 저장 위치에도 백업했어요.
  • 백업 파일을 실제로 열어 내용이 맞는지 확인했어요.
  • 제출한 버전과 제출 확인 기록을 함께 보관했어요.
