# 조건 비교 → 결정·실패 → 인수인계 시연

## 범위와 원칙

기존 프로젝트의 `Decision and handoff review` 화면을 확장합니다. AI 키 없이 직접 입력·근거 연결·명시 저장·버전 고정·Markdown 내보내기가 작동합니다. 기존 기록은 그대로 읽으며, 새 구조화 항목만 선택적으로 추가합니다. 원문에 없는 수치를 자동으로 채우거나 서로 다른 조건의 성능을 자동 순위화하지 않습니다.

## 5분 시연 순서

1. 프로젝트에서 결정·인수인계 검토 화면을 엽니다. `조건 비교`를 두 번 추가합니다.
2. 방법, 적용 조건, 평가 항목을 입력합니다. 값이 없는 경우 `원문 미보고`, `원문 접근 불가`, `추출 실패`를 구분합니다. 실제 수치가 보고된 경우 값과 단위를 원문 그대로 옮기고 아래에서 프로젝트의 논문·PDF 페이지·노트 블록·연구 페이지 근거를 연결합니다.
3. 비교 항목에서 `근거를 가져와 결정 초안 만들기`를 누릅니다. 채택·기각·보류와 이유를 직접 기록합니다. 실패 기록은 기록 종류에서 `Failed attempts`를 선택하고 재시도 조건이나 반복하지 않을 실수를 적습니다.
4. 결정에서 `근거를 가져와 후임 첫 행동 만들기`를 누릅니다. 원 결정과 비교 항목 연결이 유지됩니다. 후임이 할 구체적인 행동, 담당자, 기한, 완료 기준을 입력합니다. 행동 완료와 근거 검토 상태는 별개입니다.
5. `Save review` 후 새로고침하여 기록을 확인합니다. 근거를 직접 읽은 사람이 검토 상태와 체크리스트를 표시합니다. 검토자 이름을 적고 버전을 고정한 뒤 Markdown을 내려받습니다. 고정 버전에는 당시 값·조건·결정·후임 행동·근거 본문과 해시가 남습니다.

## 가상 시연 예시 (연구 결과가 아님)

실제 논문 수치를 꾸며 넣지 마세요. 테스트 전용 프로젝트/연구 페이지에 `가상 시연: A/B 방법을 우리 환경에서 재현하기 위한 계획`이라고 명시하고 아래 문장을 근거 노트로 씁니다.

- 비교 A: 소규모 내부 시험 환경에서 재현할 후보. 평가 항목은 처리 시간. 아직 측정하지 않았으므로 값은 비우고 미보고로 표시합니다.
- 비교 B: 메모리 사용량을 먼저 측정해야 하는 후보. 동일 조건 결과가 없으므로 직접 우열 비교를 보류합니다.
- 결정: A의 재현 절차부터 검토하고 B는 장비 조건 확인까지 보류합니다. 성능 우수성을 확정한 결정이 아닙니다.
- 실패 기록: 가상 예시에서 실행 환경이 맞지 않아 측정하지 못했습니다. 환경 버전과 실패 로그를 먼저 기록합니다.
- 후임 첫 행동: 장비·데이터·설정 값을 확인하고 최소 1회 재현합니다. 성공과 실패 로그를 모두 남기면 완료입니다.

이 예시는 가상으로 명시한 로컬/테스트 프로젝트에서만 사용합니다. 실제 연구 기록이나 계정의 기존 데이터를 덮어쓰지 않습니다.

## 안전 장치

- 출처를 연결했다고 사실이 검증됐다고 표시하지 않습니다.
- 미검토 초안과 사람이 검토한 항목을 분리합니다. AI 출처 표시를 다음 단계에도 유지합니다.
- 검토 완료된 비교·결정은 근거가 없으면 버전 고정할 수 없습니다.
- 비교/결정을 다른 기록이 참조하면 바로 삭제할 수 없습니다. 연결을 먼저 정리해야 합니다.
- 이전 버전은 새 편집으로 덮어쓰지 않습니다. 동시 수정 시 revision 충돌을 표시합니다.
- 읽기 전용 권한이나 보관 프로젝트에서는 편집하지 않습니다.
- 계정 저장, 공개 비로그인 샘플, 내 브라우저 저장의 실제 경계를 화면 표시대로 설명합니다. 저장 테스트 범위 밖의 협업·AI 검증·논문 품질 보장을 시연에서 주장하지 않습니다.
