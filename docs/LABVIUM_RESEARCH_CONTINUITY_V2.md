# 랩비움 연구 연속성 v2

랩비움은 논문을 찾고 읽는 과정을 프로젝트의 판단·실패·인수인계 기록으로 이어주는 연구 공간입니다. 이번 확장은 KU-AI 사업계획서의 ‘현재 가설, 주요 결정, 실패한 시도, 남은 질문, 다음 행동과 원문 근거를 함께 전달한다’는 목표를 실제 작업 흐름으로 옮겼습니다. 시간 절감과 구매 의향은 앞으로 검증할 가설이며 이미 입증한 성과가 아닙니다.

## 사용할 수 있는 흐름

| 화면 | 사용자가 하는 일 | 자동으로 처리하는 범위 |
| --- | --- | --- |
| 프로젝트 논문 탐색 | 주제나 실제 DOI·OpenAlex 논문을 출발점으로 후보를 살펴보고 보관·제외·읽기 대기열을 정리 | 공개 학술 API 검색, 설명 가능한 후보 정렬, 관계 지도 구성 |
| 탐색 지도 | 실제 인용 방향과 참고문헌 공유·주제 공유·텍스트 유사성을 구분하여 다음 논문으로 이동 | 확인한 공급자 관계와 계산한 유사성만 다른 선 종류로 표시 |
| 연구 도우미의 근거 미리보기 | 논문 또는 프로젝트 범위를 고르고 원문 구간을 확인·선택하여 질문과 함께 내보내기 | 선택 범위의 PDF 페이지·저장 노트·근거 노트에서 단어 기반 후보 검색 |
| 의사결정·인수인계 검토 | 가설·결정·실패·질문·다음 행동, 담당자·예정일·검토 상태·근거를 직접 기록 | 근거 연결률, 없는 참조, 원문 변경 여부와 버전 차이 계산 |
| 검토 스냅샷 | 다섯 영역을 검토하고 이름을 입력한 뒤 저장본을 명시적으로 확정 | 당시 입력·선택 근거 본문·지문값·검토자·날짜 보존, 이전 버전 비교와 Markdown 내보내기 |

새 탐색 결과와 대기열 편집은 ‘저장’을 눌러야 프로젝트 저장본에 반영됩니다. 검토 기록도 ‘검토 저장’과 ‘스냅샷 확정’이 별개입니다. 확정 뒤의 편집은 과거 스냅샷을 덮어쓰지 않습니다. 미검토 기록은 스냅샷에서도 미검토로 표시됩니다.

## AI 없이 작동하는 탐색 방법

관련 논문 후보는 제목·제공 초록 등의 TF-IDF 단어 유사도, 공급자가 기록한 실제 인용 관계, 공유 참고문헌, 공급자 주제 ID, 발행 연도와 제한적인 인용 수 맥락을 조합합니다. 유사한 후보만 반복되지 않도록 MMR 방식으로 다양성을 조정합니다. 균형·선행 연구·최근 연구·분야 연결 모드에 따라 가중치가 달라지고 추천 이유를 함께 보여줍니다.

이는 생성형 AI나 임베딩 의미 검색이 아닙니다. 저자 h-index는 이 추천 점수에 사용하지 않습니다. 일반 논문 찾기의 저자 프로필에서는 h-index를 보조 정보로 볼 수 있으나, 연구자의 분야·경력·데이터베이스 수록 범위에 영향을 받으므로 논문의 진실성이나 품질 점수로 해석하면 안 됩니다. 없는 초록·인용 정보·관계는 추측해 채우지 않습니다.

도우미의 근거 미리보기는 별도의 BM25 단어 검색입니다. 자료 전체를 모델에 자동 전송하지 않습니다. 먼저 최대 40개 후보 구간을 보여주고 사용자가 전송할 구간을 고릅니다. 현재 서버 AI 키가 없어 초안 생성은 연결되지 않았습니다. 근거 확인과 선택한 질문·자료 내보내기는 키 없이 사용할 수 있습니다. 향후 키를 연결해도 전송 확인, 최대 30개 구간 선택, AI 초안 표시와 별도 저장 절차가 유지됩니다.

## 근거를 남기는 인수인계

검토 화면은 프로젝트에 연결한 논문, 직접 연결한 근거 노트, 그 프로젝트로 지정한 연구 페이지만 출처로 제공합니다. 근거 노트만 연결한 경우 같은 논문의 나머지 내용을 자동으로 범위에 포함하지 않습니다. 특정 PDF 페이지는 Reader에서 본문을 추출한 뒤 선택합니다.

검토 완료한 가설·결정·실패 기록에 출처가 없거나 참조가 사라지면 확정할 수 없습니다. 질문과 다음 행동은 출처 없이 남길 수 있지만 확인된 사실로 취급하지 않습니다. ‘근거 연결률 100%’는 출처로 이동할 수 있다는 의미이며, 그 출처가 주장을 뒷받침하는지는 담당자가 따로 판단합니다. AI에서 온 문장은 사람이 검토한 뒤에도 출처 구분을 유지합니다.

확정 스냅샷은 당시 근거를 보존합니다. 원문이나 연결 범위가 바뀌면 최신 근거와 다르다는 표시를 보여주며, 초안을 저장한 뒤 근거가 달라진 경우 다시 검토·저장해야 확정할 수 있습니다. 변경 비교는 기록의 추가·수정·제거와 검토 목록의 변경을 보여줍니다. 변경 내역은 인수인계용 기록이며 전자서명·불변 외부 감사 시스템·규제 준수 인증을 의미하지 않습니다.

## 연구실·기업에서 검증할 가치

후임 연구자가 파일 목록을 넘겨받는 데서 그치지 않고 ‘왜 이 결정을 했는지’, ‘어떤 시도가 실패했는지’, ‘다음에 누가 무엇을 확인해야 하는지’를 근거 버전과 함께 확인하는 것이 제안 가치입니다. 별도의 연구실·기업 작업 공간과 owner/editor/viewer 권한은 구현되어 있습니다. 실시간 공동 편집, 기관 SSO, 고급 감사·보존 정책과 사내 모델 연결은 별도 제품 단계입니다. 구독·과금·온보딩 서비스의 가격과 구매 전환율은 아직 확정하거나 검증하지 않았습니다.

공식 공개 제품 설명과 비교하면 [ResearchRabbit](https://www.researchrabbit.ai/pricing)은 논문 모음·지도와 프로젝트 기능, [Litmaps](https://www.litmaps.com/pricing)는 논문 탐색 지도와 팀 기능, [Elicit](https://elicit.com/pricing)은 기업용 SSO·맞춤 자료·온보딩 등을 제공합니다. 따라서 ‘지도나 AI가 있다’는 주장만으로 차별화를 입증하지 않습니다. 랩비움이 검증할 차이는 **출처 버전을 보존한 결정·실패·인수인계 기록을 일상 연구 흐름으로 연결하는 것**입니다. 시장 우위나 경쟁 제품의 기능 부재를 입증한 비교는 아닙니다. 공식 페이지는 2026-10-14 기준으로 확인했으며 요금과 구성은 바뀔 수 있습니다.

## 한계와 보존 범위

- 학술 탐색은 공급자 첫 결과 페이지와 요청 예산 안에서 실행합니다. 전체 문헌 조사나 배경 자동 크롤링이 아닙니다. 공급자 장애·누락은 결과 한계로 표시합니다. Crossref 대체 검색에는 OpenAlex 주제·인용 확장과 같은 범위가 없습니다.
- 프로젝트 탐색과 검토 이력에는 개수·용량 한도가 있습니다. 한도를 넘으면 기존 자료를 몰래 버리거나 축약하지 않고 저장을 거절하거나 새 후보가 제외되었다고 알립니다. 검토 스냅샷은 최대 20개, 검토 이력은 프로젝트당 4MiB입니다.
- 게스트의 논문·검토 기록은 브라우저 데이터에 저장됩니다. 연구 페이지와 PDF 저장소의 동시 변경을 조정할 수 없는 브라우저에서는 연구 페이지를 근거로 한 확정을 거절하고 기존 초안을 보존합니다. 다른 탭의 직접적인 저장소 조작까지 보호하는 보안 감사 기능은 아닙니다.
- 전체 백업과 휴대용 내보내기는 저장한 프로젝트의 탐색·검토 기록을 포함합니다. 게스트 전체 백업은 실제 PDF 데이터를 포함하고 경량 백업은 PDF가 별도 필요합니다. 클라우드 전체 스냅샷은 계정에 묶인 PDF 참조를 보존하며 오프라인 PDF 파일 모음과 다릅니다. 클라우드 휴대용 내보내기의 활성 PDF 데이터 한도는 현재 20MiB입니다.
- PDF 추출·OCR 오류는 남을 수 있습니다. 본문 좌표·인용문·수치·수식과 AI 초안은 원문 대조가 필요합니다. 기능 구현과 소스 테스트만으로 실제 고객 도입, 보안 심사, 복원 수용성이나 시간 절감이 검증되지는 않습니다.

## 파일럿에서 측정할 것

사업계획서의 초기 목표를 실제 결과와 분리하여 기록합니다. 약 5명의 탐색 인터뷰와 2개 연구실 파일럿은 계획이며 진행·계약 완료를 뜻하지 않습니다.

| 검증 항목 | 비교 과제와 판정 | 초기 목표 |
| --- | --- | --- |
| 맥락 파악 시간 | 같은 자료에서 현재 가설·실패·다음 행동과 출처 찾기; 기존 폴더·위키와 랩비움의 수행 순서를 바꿔 측정 | 5분 안에 찾기, 소요 시간 중앙값 30% 단축 |
| 근거 연결 | 검토 완료한 핵심 주장 중 유효한 원문 위치가 연결된 비율 | 100% 연결; 주장 뒷받침 여부는 별도 사람 판정 |
| 인수인계 품질 | 후임이 원문을 확인해 답한 정확도, 놓친 질문, 기존 담당자에게 다시 물은 횟수 | 관찰값과 실패 사례를 함께 수집; 달성 수치 미보고 |
| 반복 사용·구매 가치 | 새 연구자 합류 외에도 결정·실패 기록이 계속 갱신되는지, PI·운영 담당자의 지불 의향 확인 | 인터뷰와 파일럿에서 검증; 가격·전환율 미확정 |

시연에서는 ‘논문 한 편 탐색 → 관계와 추천 이유 확인 → 프로젝트에 근거 연결 → 실패·결정 기록 → 사람이 검토·확정 → 근거를 바꾸고 갱신 필요 표시 확인 → 버전 비교·내보내기’ 순서를 권장합니다. 점수나 생성 문장을 성과로 대신하지 않고, 후임이 어떤 근거를 얼마나 빨리 확인했는지를 측정합니다.
